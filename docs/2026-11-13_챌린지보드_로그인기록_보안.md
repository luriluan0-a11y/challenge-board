# 챌린지 보드 로그인 기록과 보안

## 한 줄 정리

로그인 기록을 공개 GitHub 대신 비공개 Google Drive에 저장하면 공개 노출 위험은 줄지만, 저장 위치만 바꿔서 로그인 보안 전체가 해결되지는 않는다. 실제 코드와 배포 설정은 확인하지 않은 상태에서의 설계 설명이다.

## 구분할 정보

- 로그인 이력: 내부 사용자 ID, 시각, 성공·실패 등 목적에 필요한 최소 항목을 기록한다.
- 인증 비밀: 비밀번호, 세션 쿠키, 액세스 토큰은 로그에 넣지 않는다. 관리자용 비밀키를 브라우저 코드나 GitHub에 넣지 않는다.
- 인증 처리: Drive에 기록을 쓰는 것과 사용자의 신원을 검증하는 것은 별개다.

OWASP는 인증 성공·실패 기록과 로그 접근 통제를 안내하며, 비밀번호·액세스 토큰 등의 로그 기록은 피하도록 한다.
출처: [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)

## 제안하는 구조

사용자 로그인 → 서버에서 인증 검증 → 서버가 비공개 저장소에 최소 이력 기록 → 권한을 확인한 관리자만 조회.

이 저장소로 Drive를 쓸 수 있지만 파일을 공개 공유하지 않고, 일반 사용자가 다른 사람의 기록을 열람·변조하지 못하게 해야 한다. 사용자가 보낸 이메일과 성공 여부를 그대로 믿지 말고 검증한 인증 정보와 서버 시각으로 기록한다. 관리자용 Drive 자격 증명은 서버에서 관리한다. GitHub Pages 자체는 이러한 서버 처리를 제공하지 않으므로 별도 백엔드나 인증 서비스를 연결해야 한다.

Drive API는 필요한 권한만 요청한다. 예를 들어 drive.file은 앱이 사용하는 특정 파일에 대한 권한 범위다. 다만 이 범위를 선택했다고 보드 사용자별 접근 통제가 자동으로 완성되지는 않는다.
출처: [Google Drive API 권한 문서](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

위 구조는 문서의 보안 원칙을 바탕으로 한 설계 제안이다. 동시 저장, 재시도와 중복 기록 처리도 고려한다. 적절한 저장소는 이용 규모와 운영 방식에 따라 달라진다.

## 이미 GitHub에 기록을 올렸다면

파일을 지워도 과거 커밋에는 남을 수 있다. 비밀키나 토큰까지 노출했다면 해당 값을 폐기·재발급하고 필요한 Git 이력 정리도 검토한다. Drive로 옮겨도 이미 공개된 정보가 회수되는 것은 아니다.

## 다음에 확인할 것

현재 사이트가 GitHub Pages 같은 정적 사이트인지 별도 서버가 있는지, 로그인 기록이 접속 이력인지 인증 비밀까지 포함하는지 확인한다.

## 2FA 안내 문구 뜻

사용자가 본 문구: “Secure Your Account with 2FA” 및 인증 앱 코드로 본인 로그인을 확인한다는 설명.

번역: **2단계 인증으로 계정을 보호하세요. 인증 앱에서 생성된 코드는 누군가 내 로그인 정보를 알아내더라도 실제로 로그인하는 사람이 본인인지 확인하는 데 도움이 됩니다.**

2FA는 Two-Factor Authentication(이중 인증)이다. 이 문맥에서는 비밀번호에 더해, 미리 계정에 연결한 인증 앱의 일회용 숫자 코드로 한 번 더 확인한다는 뜻이다. 코드를 요구하는 화면이라면 연결해 둔 인증 앱을 열어 해당 계정의 코드를 입력한다. 설정 중이라면 보통 화면의 QR 코드를 인증 앱에 등록한 뒤 생성되는 코드를 입력한다. 현재 문구만으로 설정 단계인지 로그인 단계인지는 판단할 수 없다.

출처: [Login.gov 인증 앱 안내](https://www.login.gov/help/create-account/authentication-methods/authentication-application/)

## gas 폴더와 배포용 파일 구분 (2026-11-13)

질문: 배포용 파일을 올릴 때 gas 폴더는 빼야 할까?

**웹사이트 배포 결과물에서는 제외하는 것이 맞다. GitHub 소스 저장소에 보관하는 것은 별개의 판단이다.** gas/Auth.js와 gas/Code.js는 Google Apps Script에서 실행하는 서버 코드이며, 정적 사이트에 올려도 서버 기능으로 실행되지 않는다. 비밀이나 실제 개인정보가 없는 서버 소스는 GitHub에서 관리할 수 있지만, 자격 증명·명단·로그 파일은 올리지 않는다. 이번에는 전체 보안 감사를 수행하지 않았다.

현재 로컬 vercel.json은 테스트 후 index.html, styles.css, src만 dist로 복사하고 dist를 배포하도록 되어 있다. 따라서 이 설정대로 배포하면 gas, docs, tests는 웹 배포 결과물에 포함되지 않는다. 현재 GitHub Actions도 Pages 배포 대신 테스트만 수행하도록 되어 있다. 설정 파일 확인 결과이며 실제 원격 서비스 설정까지 확인한 것은 아니다.

- 웹사이트 배포: index.html, styles.css, src/
- Apps Script 배포: gas/Code.js → Code.gs, gas/Auth.js → Auth.gs, appsscript.json은 Apps Script 매니페스트 설정에 반영
- GitHub 소스 보관: 코드·테스트·설정 중 공개해도 되는 파일
- 공개 제외: 비밀키, 토큰, 실제 학생 명단, 로그인·세션 기록, 개인 메모

.gitignore는 새 파일의 Git 추적을 제어한다. 이미 추적 중인 파일을 숨기거나, 웹 배포 파일을 자동으로 골라 주는 설정이 아니다.

참고: [GitHub 정적 배포 산출물 지정](https://github.com/actions/upload-pages-artifact/blob/main/README.md), [Apps Script 설정 값 저장](https://developers.google.com/apps-script/guides/properties)
